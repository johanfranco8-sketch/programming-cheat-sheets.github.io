Control de versiones

Git

Comandos y flujos de trabajo para registrar cambios, colaborar y recuperar versiones con confianza.

Configuración e inicio

git config --global user.name "Tu Nombre"
git config --global user.email "correo@ejemplo.com"
git init
git clone https://github.com/usuario/proyecto.git
git status

git status es el punto de partida: muestra rama, archivos modificados, área de preparación y conflictos.

Inspeccionar y confirmar

git diff                 # cambios sin preparar
git diff --staged        # cambios preparados
git add ruta/archivo
git commit -m "feat: agrega búsqueda de guías"
git log --oneline --graph --decorate -20
Buen commit: agrupa un cambio coherente, evita archivos accidentales y explica la intención en modo imperativo.

Ramas, merge y rebase

git switch -c feat/buscador
# trabajo y commits
git switch main
git merge feat/buscador

# actualizar una rama local antes de compartirla
git switch feat/buscador
git rebase main
  • Usa ramas cortas y nombres descriptivos.
  • Resuelve conflictos revisando el resultado completo, no solo los marcadores.
  • No reescribas con rebase commits públicos que otras personas ya consumen.
  • Ejecuta pruebas después de una fusión o rebase.

Repositorios remotos

git remote -v
git fetch origin
git pull --ff-only origin main
git push -u origin feat/buscador
git branch -r

fetch descarga referencias sin modificar tu rama; pull descarga e integra. Revisa antes de integrar cambios ajenos.

Deshacer y recuperar

git restore archivo.txt
git restore --staged archivo.txt
git revert <commit>
git reflog
git switch --detach <commit>

restore

Restaura archivos o los retira del área de preparación.

revert

Crea un commit inverso seguro para historial compartido.

reflog

Encuentra referencias recientes aunque una rama haya cambiado.

Cuidado: reset --hard y clean -fd pueden borrar trabajo local; inspecciona y respalda antes.
